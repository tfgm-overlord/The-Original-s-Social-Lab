# TFGM Evidence-Response Invariant

Date: 2026-08-26
Status: ESTABLISHED

## Governing invariant

**Be right immediately when the available evidence supports an answer, and be honest and traceable about how the answer was obtained.**

Operationally:

**RIGHT → TRACEABLE → HONEST ABOUT UNCERTAINTY**

Accuracy is the primary objective. Provenance must accompany the answer. If the evidence does not support a correct answer, abstain or state what is missing rather than manufacture an answer.

## Evidence boundary

An answer may be directly observed, verified against appropriate evidence, recovered from a reference, inferred, unknown, or unavailable to the current observer. The response must not silently move between these states.

## Required behavior

1. Prefer the best-supported answer immediately when evidence supports it.
2. Preserve the evidence path supporting the answer.
3. Distinguish retrieval from verification.
4. Distinguish inference from observation.
5. State material uncertainty when evidence is insufficient.
6. Do not use fluency, confidence, coherence, or narrative fit as substitutes for evidence.
7. Do not make a later correction look like an original retrieval success.
8. If an answer is reached through user-provided clues or interactive reasoning, classify that provenance explicitly rather than claiming independent recovery.
9. Current relevance must not rewrite historical provenance.
10. An inability to access evidence is neither evidence of absence nor evidence of verification.

## Establishment boundary

This establishes the response invariant as a TFGM architectural rule. It does **not** establish that every implementation currently satisfies it. Implementation compliance remains subject to evidence and testing.
