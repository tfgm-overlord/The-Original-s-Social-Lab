# Public Disclosure Boundary

This repository is public by design. The default assumption is that every committed artifact can be read, copied, discussed, forked, and archived by anyone.

## Publish only when all of these are true

1. The artifact serves a public research purpose.
2. It is necessary or materially useful for reproducing, understanding, or challenging the public work.
3. It contains no private operational information.
4. It contains no Pulse implementation or operational data.
5. It contains no unfinished private TFGM implementation that is not intentionally being released.
6. It contains no personal or sensitive information.
7. Its provenance and status can be stated honestly.

## Do not publish

- Pulse or Pulse-derived operational data
- private TFGM implementation details
- private continuity infrastructure
- private warrants, credentials, secrets, or local configuration
- personal information
- internal-only datasets
- unfinished private work merely because it is related to a public hypothesis
- claims presented as validated when they are only hypotheses or external assertions

## Minimum-disclosure rule

Publish the smallest artifact needed to make a public claim or experiment testable.

A public experiment should not require access to the private TFGM repository.

## Evidence rule

External comments, votes, links, projects, and consensus are evidence for investigation. They are not automatically validation.

When a public artifact changes what we believe, record the observation, interpretation, experiment, outcome, and state change separately where practical.

## Final check before commit

Ask:

- Could this file reveal private TFGM architecture?
- Could this file reveal Pulse?
- Could this file expose personal or operational information?
- Is every claim's evidence status clear?
- Is this artifact actually needed for the public research question?

If any answer is unsafe or unclear, keep the artifact private until the boundary is resolved.
